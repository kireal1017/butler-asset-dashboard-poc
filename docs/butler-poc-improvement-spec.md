# 버틀러 자산 PoC 수정 계획안 v3 — 건물·호실·계약 구조와 자산 분석

- 작성일: 2026-10-08 (v3)
- 대상: 기존 '자산 현황 대시보드' PoC (Vue.js + SQLite, 모바일 폭 전용, 서울 한정, 로그인 없음)
- 근거 문서: 노션 '261008 - 버틀러 서비스 조사 보고서', '261008 - 버틀러 자산 가치 PoC 기획안'
- 화면 흐름 참고: 임대관리 앱 '랜들리'의 임대인 화면(전체 메뉴, 건물 관리, 새 건물 등록, 건물 상세, 호실 등록, 자산 분석, 계약 관리). 참고 이미지는 전달하지 않으므로, 이 문서만 보고 구현할 수 있게 화면 구성을 글로 모두 풀어 적었다.

## 0. 작업 전에 (Claude Code에게)

1. 먼저 기존 코드의 라우트, 컴포넌트, DB 스키마, 실거래 수집 모듈을 읽고 이 문서의 이름을 기존 이름에 맞춘다. 이 문서의 테이블·컬럼·컴포넌트 이름은 예시다.
2. **시각 디자인은 기존 PoC의 것을 그대로 쓴다.** 색, 글꼴, 모서리, 여백, 버튼 모양을 새로 정하지 않는다. 이 문서는 "어느 화면에 무엇이 어떤 순서로 놓이고, 누르면 무슨 일이 일어나는지"만 정한다. 3장의 구성 요소가 기존 코드에 있으면 그것을 쓰고, 없으면 기존 스타일에 맞춰 만든다.
3. "유지"로 적힌 기존 기능은 동작을 바꾸지 않는다. 특히 단지 검색, 면적·층 자동 조회, 참고가 계산, 비교 3가지는 **로직을 그대로 재사용**한다.
4. **더미데이터를 쓰지 않는다.** 시드 데이터, 샘플 행, 하드코딩한 예시 값을 넣지 않는다. 화면의 모든 값은 외부 API에서 불러온 값이거나 사용자가 입력한 값이다(5장). API가 실패하면 예시 값으로 대체하지 말고 오류·빈 상태를 보여준다. 이 문서에 적힌 금액·날짜·단지명은 화면 모양을 설명하는 예시이며 코드에 넣지 않는다.
5. **구현하지 않는 기능은 화면에도 두지 않는다.** '준비 중' 메뉴, 비활성 버튼, 하단 탭, 자리만 잡아둔 영역을 만들지 않는다(10장).
6. **DB는 새 스키마로 빈 상태에서 시작한다.** 기존에 등록한 자산은 옮기지 않는다. 운영자가 처음부터 다시 등록한다.
7. 9장의 단계 순서대로 진행하고, 단계가 끝날 때마다 실제 화면에서 동작을 확인한다.
8. 외부 API의 요청 인자와 응답 필드명은 실제 응답을 한 번 찍어서 확인한다.

## 2. 전체 구조

### 2.1 개념

| 개념 | 뜻 | 예 |
|---|---|---|
| 건물 | 아파트 단지 하나. 주소로 찾아 등록한다 | ○○아파트 |
| 호실 | 건물 안에서 내가 가진 한 세대. 동·호, 면적·층, 매입 정보를 가진다 | 101동 1203호 |
| 계약 | 호실에 걸린 임대차 계약. 한 호실에 시간순으로 여러 건이 쌓인다 | 2025.09 ~ 2027.08 월세 |

### 2.2 화면 목록과 이동

**하단 탭은 만들지 않는다.** 앱을 열면 전체 메뉴가 나오고, 모든 이동은 메뉴 행·카드·버튼과 헤더의 뒤로가기로 한다.

| 번호 | 화면 | 들어오는 길 |
|---|---|---|
| 4.1 | 전체 메뉴 (첫 화면) | 앱 시작 |
| 4.2 | 건물 관리 | 전체 메뉴 |
| 4.3 | 새 건물 등록 / 건물 수정 | 건물 관리, 건물 상세, 자산 분석 빈 상태 |
| 4.4 | 건물 상세 | 건물 관리의 건물 카드 |
| 4.5 | 호실 등록 / 호실 수정 | 건물 상세, 호실 상세 |
| 4.6 | 호실 상세 | 건물 상세의 호실 카드 |
| 4.7 | 자산 분석 — 목록 | 전체 메뉴 |
| 4.8 | 자산 분석 — 상세 | 자산 분석 목록, 건물 상세, 호실 상세 |
| 4.9 | 계약 관리 | 전체 메뉴 |
| 4.10 | 계약 등록 / 계약 수정 | 계약 관리, 호실 상세, 호실 카드 |

처음 쓰는 사람의 흐름:

```
전체 메뉴 → 건물 관리(빈 상태) → 새 건물 등록 → 건물 상세(호실 없음) → 호실 등록
 → 건물 상세(호실 카드) → 계약 등록 → 건물 상세 → (전체 메뉴) → 자산 분석 → 건물 선택 → 상세
```

## 3. 공통 구성 요소

화면 설명에서 반복해서 쓰는 이름이다. 모양은 기존 디자인을 따르고, 여기서는 **안에 무엇이 들어가는지**만 정한다.

| 이름 | 구성 |
|---|---|
| 헤더 | 왼쪽 뒤로가기 버튼(전체 메뉴에는 없음), 제목, 필요하면 제목 아래 작은 보조 줄(주소 등), 오른쪽에 주 버튼 하나(예: `+ 건물 추가`) |
| 요약 카드 | 화면 맨 위의 강조 카드. 윗줄에 작은 라벨과 큰 숫자, 구분선 아래에 3칸 집계(각 칸은 라벨 + 숫자) |
| 통계 타일 | 가로로 나란한 작은 카드 3개. 각각 큰 숫자와 그 아래 라벨 |
| 필터 칩 | 가로로 나열한 선택 버튼. 하나만 선택되고, 라벨 뒤에 건수를 붙인다. 선택하면 아래 목록이 걸러진다 |
| 상태 뱃지 | 카드 제목 옆의 작은 표시. 정상·주의·중립 세 가지 톤 |
| 안내 박스 | 화면 위쪽의 한두 줄 메시지. 정보·성공·경고·오류 네 종류. 경고에는 버튼 하나가 붙을 수 있다 |
| 입력 카드 | 카드 위에 소제목(예: "기본 정보"), 카드 안에 입력 필드를 세로로 쌓은 것. 필드마다 위에 라벨, 필수는 `*`, 선택은 "(선택)", 아래에 작은 도움말 |
| 정보 행 | 카드 안의 한 줄. 왼쪽에 라벨, 오른쪽에 값. 카드에서 가장 중요한 값 하나만 강조 |
| 바텀시트 | 뒤 화면을 어둡게 하고 아래에서 올라오는 패널. 위쪽에 제목과 닫기(X) |
| 빈 상태 | 카드 가운데에 아이콘, 굵은 한 줄, 설명 한두 줄, 버튼 하나 |
| 추가 카드 | 목록 맨 아래의 점선 테두리 카드. 왼쪽에 제목과 설명, 오른쪽에 `+` 버튼 |
| 메뉴 행 | 왼쪽 아이콘, 가운데 제목과 설명, 오른쪽 `›`. 행 전체를 누를 수 있다 |
| 폼 버튼 줄 | 폼 맨 아래에 버튼 두 개를 나란히. 왼쪽 `취소`(보조), 오른쪽 등록 버튼(주) |
| 호실 카드 | 3.1 참고 |
| 등록 방식 전환 | 3.2 참고 |

문구는 해요체로 쓴다("~해요", "~있어요"). 금액은 큰 값은 `6억 2,000만원`, 월세는 `80만원`, 계약 카드의 보증금은 원 단위 `50,000,000원`으로 적는다. 등락 표시는 기존 PoC 방식을 유지한다.

### 3.1 호실 카드

건물 상세에서 쓰는 카드. 누르면 호실 상세(4.6)로 간다.

계약이 있을 때(임대 중, 만료 임박):

```
① 101동 1203호                              [임대 중]
② 보증금 5,000만원 · 월세 80만원
③ 계약 만료 2027.08.31 (D-327)
─────────────────────────────────────────────
④ 최근 실거래 참고가 6억 2,000만원   ▲ 2억 1,000만 (+51.2%)
⑤ 기준일 2026.08.12
```

- ① 제목과 상태 뱃지.
- ② 전세 계약이면 "보증금 3억 5,000만원 · 전세". 임차인 이름을 입력했으면 줄 끝에 " · 김○○".
- ③ 만료 임박이면 뱃지를 `[만료 임박 D-45]`로 쓴다.
- ④ 왼쪽에 참고가, 오른쪽에 매입가 대비 등락(금액과 %).

계약이 없을 때(공실, 입주 예정): 참고가를 크게 보여준다.

```
① 101동 1203호                              [공실]
② 최근 실거래 참고가
③ 6억 2,000만원            ▲ 2억 1,000만 (+51.2%) 매입가 대비
④ 기준일 2026.08.12
⑤ [ 임대 계약 등록하기 ]
```

- 입주 예정이면 ⑤ 대신 "2026.11.01 입주 예정 · 보증금 5,000만원 · 월세 80만원"을 쓴다.
- ⑤ 버튼은 계약 등록(4.10)으로 가며, 이 호실이 미리 선택된다. 버튼을 눌렀을 때는 카드의 이동(호실 상세)이 같이 일어나지 않게 한다.

참고가를 계산할 거래가 없으면 참고가 자리에 "최근 12개월 안에 같은 면적 거래가 없어요"를 쓰고 등락은 숨긴다.

### 3.2 등록 방식 전환

새 건물 등록(4.3)과 호실 등록(4.5) 화면에 둔다. 안내 박스 아래, 입력 카드 위에 가로로 나란한 두 칸짜리 선택 버튼이다.

| 선택 | 동작 |
|---|---|
| `순서대로 등록하기` (기본) | 입력을 단계로 나눠 한 화면에 한 단계씩 보여준다. 전환 버튼 아래에 "1 / 2" 같은 단계 표시를 둔다. 폼 버튼 줄은 첫 단계에서 `취소` · `다음`, 마지막 단계에서 `이전` · 등록 버튼. 그 단계의 필수값이 채워져야 `다음`이 눌린다. 기존 PoC의 등록 흐름(단지 검색 → 동·호 입력 → 매입 정보)과 같은 순서이므로 기존 단계 화면을 재사용한다 |
| `한 번에 등록하기` | 모든 입력 카드를 한 화면에 세로로 쌓아 보여준다. 폼 버튼 줄은 `취소` · 등록 버튼 |

- 두 방식은 입력 항목, 검증, 저장 로직이 같다. 보여주는 방법만 다르다.
- 중간에 방식을 바꿔도 이미 입력한 값은 유지된다. `한 번에`에서 `순서대로`로 바꾸면 첫 단계부터 보여준다.
- 수정 화면(건물 수정, 호실 수정)에는 전환을 두지 않고 한 화면으로 보여준다.

## 4. 화면별 명세

각 화면은 위에서 아래 순서로 적었다.

### 4.1 전체 메뉴 (첫 화면)

앱을 열면 이 화면이 나온다. 홈 화면을 따로 두지 않는다.

1. **헤더**: 제목 "전체 메뉴", 그 아래 보조 줄 "모든 기능을 여기에서 찾을 수 있어요". 뒤로가기, 검색창, 오른쪽 버튼 없음.
2. **그룹 카드 2개**. 카드마다 맨 위에 작은 그룹 제목, 그 아래 메뉴 행을 구분선으로 나눠 쌓는다.

| 그룹 제목 | 메뉴 | 설명 | 이동 |
|---|---|---|---|
| 건물 · 호실 | 건물 관리 | 건물·호실 등록과 현황 | 4.2 |
| 건물 · 호실 | 자산 분석 | 주변 시세와 내 건물 위치 | 4.7 |
| 계약 | 계약 관리 | 계약 목록과 등록 | 4.9 |

이 세 개 말고는 넣지 않는다. 메뉴는 해당 화면이 구현된 단계에서 추가한다(9장).

### 4.2 건물 관리

1. **헤더**: 뒤로가기(→ 전체 메뉴), 제목 "건물 관리", 오른쪽 `+ 건물 추가` → 4.3
2. **요약 카드**: 라벨 "전체 건물", 숫자 "N개". 3칸 집계는 `운영 중 · 등록 중 · 확인 필요`(7.2)
3. **검색 입력**: "건물 이름 또는 주소 검색". 입력하는 즉시 아래 목록을 걸러낸다(서버 호출 없이 이름·주소 포함 여부로).
4. **필터 칩**: 전체 · 운영 중 · 등록 중 · 확인 필요
5. **건물 카드 목록**. 카드 하나의 구성:
   - 윗줄: 건물 아이콘, 건물명(굵게), 오른쪽에 상태 뱃지
   - 건물명 아래: 주소 한 줄(넘치면 말줄임)
   - 구분선
   - 아랫줄: "입주율 100%", 가로 진행 막대, 오른쪽 끝에 "1/1"(임대 중인 호실 수 / 보유 호실 수, 7.2)
   - 카드를 누르면 건물 상세(4.4)
6. **추가 카드**: 제목 "새 건물 추가하기", 설명 "건물 정보를 등록하고 관리를 시작해요", `+` → 4.3

건물이 없으면 2~5를 숨기고 빈 상태("아직 등록한 건물이 없어요" / "건물을 등록하면 호실과 계약을 관리할 수 있어요." / `첫 건물 등록하기`)를 보여준다.

### 4.3 새 건물 등록 / 건물 수정

1. **헤더**: 뒤로가기, 제목 "새 건물 등록"
2. **정보 안내 박스**: 건물 아이콘, 제목 "건물 정보를 등록해요", 설명 "기본 정보를 저장한 뒤 호실과 계약을 추가하면 관리를 시작할 수 있어요."
3. **오류 안내 박스** (등록을 눌렀는데 문제가 있을 때만): "건물명과 주소는 필수예요."
4. **등록 방식 전환**(3.2)
5. **입력 카드 '기본 정보'**

| 필드 | 동작 |
|---|---|
| 주소 `*` | 직접 타이핑하지 않는다. 필드를 누르면 주소 검색 바텀시트가 열린다. 비어 있을 때 안내 문구는 "눌러서 주소를 검색해요" |
| 건물명 `*` | 주소를 고르면 단지명이 자동으로 들어간다. 사용자가 고칠 수 있다 |
| 보유 호실 수 | 숫자, 1 이상, 기본 1. 도움말 "이 건물에서 내가 가진 호실 수예요. 각 호실 정보는 다음에 추가해요" |
| 설명 (선택) | 여러 줄 메모. 안내 문구 "건물에 대한 메모를 적어요" |

6. **'다음 단계' 안내 카드**: 제목 "다음 단계", 번호가 붙은 세 줄 — ① 건물 기본 정보를 저장해요 ② 호실을 등록해요 ③ 임대 계약을 추가해요
7. **폼 버튼 줄**: `취소` · `건물 등록`

`순서대로 등록하기`일 때의 단계:

| 단계 | 보여주는 것 |
|---|---|
| 1 / 2 주소 찾기 | 주소 필드만. 주소를 골라야 `다음`이 눌린다 |
| 2 / 2 건물 정보 | 고른 주소(읽기 전용 한 줄), 건물명, 보유 호실 수, 설명 |

**주소 검색 바텀시트**

- 위: 제목 "주소 검색", 닫기(X)
- 그 아래: 입력창("단지명 또는 주소로 검색")과 `검색` 버튼을 한 줄에. 시트가 열리면 입력창에 바로 커서가 간다. 엔터로도 검색된다.
- 검색 전: 가운데에 안내 "단지 이름이나 동 이름으로 찾을 수 있어요."
- 검색 후: 결과 목록. 한 줄마다 단지명(굵게)과 그 아래 주소. 결과가 없으면 "검색 결과가 없어요. 다른 이름으로 찾아보세요."
- 결과를 누르면 시트가 닫히고 주소 필드가 채워진다. 건물명이 비어 있으면 단지명을 채운다.
- 검색은 **기존 PoC의 단지 검색 로직**을 쓴다(새 주소 API를 붙이지 않는다). 고른 결과에서 시군구코드, 법정동코드, 지번(본번·부번), 실거래 단지명을 함께 받아 건물에 저장한다(실거래·건축물대장 조회에 쓴다).

**등록하면**

1. 건물을 만든다. 같은 단지를 이미 등록했으면 만들지 않고 오류 박스 "이미 등록한 건물이에요."
2. 서버가 건축물대장을 조회해 저장한다(8.3). 실패해도 건물 등록은 끝낸다.
3. 건물 상세(4.4)로 가고, 맨 위에 성공 안내 박스 "건물이 등록됐어요. 이제 호실을 추가해 보세요."를 보여준다.

**건물 수정**: 같은 입력 카드를 쓰고 제목만 "건물 정보 수정". 주소는 읽기 전용. 보유 호실 수는 이미 등록한 호실 수보다 작게 할 수 없다. 맨 아래에 `건물 삭제`가 있고, 호실이 하나라도 있으면 "호실을 먼저 삭제해 주세요."라고 안내하고 삭제하지 않는다.

### 4.4 건물 상세

1. **헤더**: 뒤로가기, 제목 = 건물명, 보조 줄 = 주소, 오른쪽 `+ 호실 등록` → 4.5
2. **성공 안내 박스** (건물이나 호실을 등록한 직후 한 번만)
3. **통계 타일 3개**: `임대 중 · 공실 · 입주 예정` (여기서는 만료 임박을 임대 중에 넣는다)
4. **필터 칩**: 전체 N · 임대 중 · 공실 · 입주 예정
5. **호실 카드 목록**(3.1). 동·호 순서. 호실이 없으면 빈 상태: "아직 등록한 호실이 없어요" / "호실을 등록하면 계약과 시세를 관리할 수 있어요." / `첫 호실 등록하기` → 4.5
6. **메뉴 행 2개** (카드 하나에 묶어서):
   - "자산 분석" / "주변 시세와 내 건물 위치" → 4.8 (이 건물)
   - "건물 정보 수정" / "이름·보유 호실 수·메모 수정, 건물 삭제" → 4.3 수정

### 4.5 호실 등록 / 호실 수정

1. **헤더**: 뒤로가기, 제목 "호실 등록"
2. **정보 안내 박스**: 문 아이콘, 제목 "{건물명} · 새 호실 등록", 설명 "동과 호를 입력하면 면적과 층을 불러와요. 보증금과 월세는 계약 등록에서 입력해요."
3. **등록 현황 박스** (한 줄짜리 정보 박스): "등록 가능 **1개** 남음 · 전체 1개 중 0개 등록됨". '전체'는 건물의 보유 호실 수, '등록됨'은 이 건물에 등록한 호실 수다.
   - 남은 수가 0이면 이 박스를 경고 톤으로 바꿔 "보유 호실을 모두 등록했어요."와 버튼 `보유 호실 수 늘리기`(→ 4.3 수정)를 보여주고, 아래의 4~7은 숨긴다.
4. **오류 안내 박스** (필요할 때만)
5. **등록 방식 전환**(3.2)
6. **입력 카드 '기본 정보'**

| 필드 | 동작 |
|---|---|
| 동 `*`, 호 `*` | 한 줄에 나란히. 둘 다 입력하면 기존 PoC의 면적·층 자동 조회를 실행한다 |
| 전용면적, 층 | 조회 결과를 읽기 전용 정보 행으로 보여준다. 조회 중에는 로딩 표시. 실패하면 오류 박스 "면적과 층을 불러오지 못했어요. 동·호를 다시 확인해 주세요." (기존 PoC가 실패를 다르게 처리하고 있으면 그 방식을 따른다) |

7. **입력 카드 '매입 정보'**

| 필드 | 동작 |
|---|---|
| 취득 연월 `*` | 연·월 선택 |
| 매입가 `*` | 원 단위 입력. 필드 아래에 "4억 1,000만원" 식으로 읽어준다 |
| 매입가 제안 | 취득 연월과 면적이 모두 정해지면 매입가 필드 아래에 한 줄이 나타난다: "2016년 10월 같은 단지·같은 면적 실거래 평균 4억 1,000만원 (3건)" + 버튼 `이 금액 넣기`. 누르면 매입가에 들어가고 사용자가 고칠 수 있다. 그 달에 거래가 없으면 3개월, 6개월로 넓혀 찾고(7.7) "2016년 8월~10월 평균 …"처럼 기간을 밝힌다. 6개월에도 없으면 "취득 시점 6개월 안에 같은 면적 거래가 없어요. 직접 입력해 주세요." |

8. **폼 버튼 줄**: `취소` · `호실 등록`

`순서대로 등록하기`일 때의 단계:

| 단계 | 보여주는 것 |
|---|---|
| 1 / 2 호실 찾기 | '기본 정보' 카드. 면적·층 조회가 끝나야 `다음`이 눌린다 |
| 2 / 2 매입 정보 | 고른 호실 요약(읽기 전용 한 줄: "101동 1203호 · 전용 84.9㎡ · 12층"), '매입 정보' 카드 |

참고 앱의 호실 등록에 있는 방 구성과 설비 선택은 넣지 않는다(쓰는 화면이 없다).

**등록하면**

1. 필수값이 비면 오류 박스 "동·호, 취득 연월, 매입가는 필수예요." 같은 건물에 같은 동·호가 있으면 "이미 등록한 호실이에요."
2. 호실과 보유 정보를 만든다.
3. 서버가 매매 실거래를 수집해 참고가를 계산한다(기존 로직). 이어서 전월세 실거래를 수집한다. 수집하는 동안 기존 PoC의 로딩 표시를 쓴다. 전월세 수집이 실패해도 등록은 끝낸다.
4. 건물 상세(4.4)로 돌아가고, 맨 위에 성공 안내 박스 "호실이 등록됐어요. 이제 임대 계약을 추가해 보세요."를 보여준다. 새 호실 카드에는 `임대 계약 등록하기` 버튼이 보인다.

**호실 수정**: 제목 "호실 정보 수정". 동·호·면적·층은 읽기 전용, 취득 연월과 매입가만 고친다. 맨 아래 `호실 삭제`는 확인을 받은 뒤 그 호실의 계약과 참고가 기록을 함께 지운다.

### 4.6 호실 상세

호실 하나의 계약과 매입 정보를 본다. 시세 분석은 자산 분석 상세(4.8)에서 본다.

1. **헤더**: 뒤로가기, 제목 "101동 1203호", 보조 줄 "건물명 · 전용 84.9㎡ · 12층", 오른쪽 `수정` → 4.5 수정

2. **카드 ① 임대 현황**

카드 제목 오른쪽에 `수정`(계약이 있을 때, → 4.10 수정). 정보 행:

| 라벨 | 값 |
|---|---|
| 상태 | 상태 뱃지 |
| 임차인 | 김○○ (입력했을 때만) |
| 보증금 | 5,000만원 |
| 월세 | 80만원 (전세면 "전세") |
| 환산 월세 | 99만원 ← 이 카드에서 강조하는 값 |
| 계약 기간 | 2025.09.01 ~ 2027.08.31 (D-327) |

- 카드 아래 작은 주석: "보증금은 전월세전환율 r%(서울, 기준 YYYY.MM)로 월세로 바꿔 더했어요."
- 계약이 없으면 정보 행 대신 빈 상태: "등록한 계약이 없어요" / "계약을 등록하면 만료일과 임대 수준을 볼 수 있어요." / `첫 계약 등록하기` → 4.10
- 입주 예정 계약만 있으면 같은 정보 행을 보여주되 상태 뱃지를 '입주 예정'으로 쓴다.

3. **카드 ② 매입과 시세**

| 라벨 | 값 |
|---|---|
| 취득 연월 | 2016.10 |
| 매입가 | 4억 1,000만원 |
| 최근 실거래 참고가 | 6억 2,000만원 ← 강조 |
| 기준일 | 2026.08.12 |
| 매입가 대비 | ▲ 2억 1,000만 (+51.2%) |

4. **메뉴 행 1개**: "자산 분석" / "주변 시세와 실거래 자세히 보기" → 4.8 (이 건물, 이 호실 선택)

### 4.7 자산 분석 — 목록

전체 메뉴에서 '자산 분석'을 누르면 먼저 내가 가진 건물 목록이 나온다.

1. **헤더**: 뒤로가기(→ 전체 메뉴), 제목 "자산 분석"
2. **정보 안내 박스** (두 문장): "국토교통부 실거래가로 **내 건물이 주변과 비교해 어느 수준인지** 보여드려요." / "건물을 고르면 주변 전월세 시세, 매매 실거래, 건축물대장을 확인할 수 있어요." 첫 문장의 가운데 구절만 굵게.
3. **건물 카드 목록**. 카드 하나의 구성(4.2의 건물 카드보다 단순하다):
   - 첫 줄: 건물명(굵게)
   - 둘째 줄: 주소(작게, 넘치면 말줄임)
   - 셋째 줄: "호실 1개"
   - 오른쪽 가운데에 `›`
   - 카드를 누르면 자산 분석 상세(4.8)

건물이 없으면 3 대신 빈 상태: "아직 등록한 건물이 없어요" / "건물과 호실을 등록하면 시세를 분석해 드려요." / `첫 건물 등록하기` → 4.3

### 4.8 자산 분석 — 상세

건물 하나의 임대 수준과 시세를 본다. 카드 네 개를 세로로 쌓는다.

1. **헤더**: 뒤로가기, 제목 = 건물명, 보조 줄 = 주소
2. **호실 선택 칩** (이 건물에 호실이 2개 이상일 때만): "101동 1203호" 같은 칩을 가로로. 기본은 첫 번째 호실, 호실 상세에서 들어오면 그 호실. 선택한 호실은 카드 ②와 ③에 적용된다. 카드 ①과 ④는 건물 전체 기준이다.

호실이 하나도 없으면 2~5 대신 빈 상태: "등록한 호실이 없어요" / "호실을 등록하면 시세를 분석해 드려요." / `호실 등록하기` → 4.5. 그 아래에 카드 ④(건축물대장)만 보여준다.

3. **카드 ① 내 건물** — 이 건물에서 지금 임대 중인 호실(만료 임박 포함)의 계약을 모아 계산한다(7.5).

| 라벨 | 값 |
|---|---|
| 평균 월세 | 80만원 |
| 환산 월세 | 99만원 ← 강조 |
| 평균 보증금 | 5,000만원 |
| 평균 면적 | 84.0㎡ |
| ㎡당 환산 월세 | 11,786원 |

- 카드 아래 주석(작게, 두 줄): "계약에 등록한 값이에요." / "보증금은 **전월세전환율 r%**(서울, 기준 YYYY.MM)로 월세로 바꿔 더했어요 — 보증금을 빼고 월세만 보면 실제보다 낮아 보여요."
- 임대 중인 호실이 없으면 정보 행 대신: "임대 중인 계약이 없어요. 계약을 등록하면 내 건물의 임대 수준을 볼 수 있어요." + `계약 등록하기` → 4.10

4. **카드 ② 주변 전월세 시세** — 선택한 호실과 같은 단지·비슷한 면적의 최근 전월세 실거래(7.6).

- 정보 행: 주변 평균 환산 월세(강조) / 범위(최저 ~ 최고) / 거래("최근 6개월 7건")
- 그 호실이 임대 중이면 정보 행 아래 한 줄 결론: "내 환산 월세가 주변 평균보다 8% 낮아요"(또는 "높아요", "비슷해요")
- 임대 중이 아니어도 주변 평균은 보여준다(임대료를 정할 때 참고).
- 거래가 부족하면 정보 행 대신 가운데 정렬 두 줄: "비교할 만한 최근 거래가 아직 충분하지 않아요 (최근 12개월 n건)." / "거래가 쌓이면 자동으로 보여드릴게요."
- 카드 아래 작은 글씨: "출처 국토교통부 전월세 실거래가"

5. **카드 ③ 매매 시세** — 선택한 호실 기준. 카드 제목 오른쪽에 `새로고침`(7.3). 위에서 아래로:

   1. 큰 글씨: 최근 실거래 참고가
   2. 작은 글씨: "기준일 2026.08.12 · 같은 단지·같은 면적 최근 거래 n건 기준"
   3. 정보 행: 취득 연월 / 매입가 / 매입가 대비(금액과 %)
   4. **기간별 실거래 평균** (소제목). 정보 행 3개:

      | 라벨 | 값 |
      |---|---|
      | 최근 1개월 | 6억 2,000만원 (1건) |
      | 최근 3개월 | 6억 1,000만원 (4건) |
      | 최근 6개월 | 6억 500만원 (9건) |

      거래가 없는 기간은 값 자리에 "거래 없음". 소제목 아래 작은 글씨: "같은 단지·같은 면적 기준이에요. 실거래 신고가 늦게 올라와 최근 1개월은 건수가 적을 수 있어요."
   5. **가격 위치 막대**(7.4)
   6. **비교 3가지**: 기존 PoC의 구성과 값 그대로
   7. **최근 실거래** (소제목): 같은 단지·같은 면적 최근 5건을 한 줄씩(계약일 / 층 / 금액). 5건이 안 되면 있는 만큼, 없으면 "최근 12개월 안에 같은 면적 거래가 없어요."
   8. 카드 아래 작은 글씨: "출처 국토교통부 실거래가"

6. **카드 ④ 건축물대장**

- 정보 행: 주용도 / 구조 / 사용승인일("1999.05.20 · 준공 28년차") / 층수("지상 15층 · 지하 1층") / 세대수 / 주차 대수 / 연면적. 값이 없는 행은 숨긴다.
- 카드 아래 작은 글씨: "출처 국토교통부 건축물대장"
- 조회에 실패했으면 정보 행 대신 "건축물대장 정보를 불러오지 못했어요." + `다시 시도`

### 4.9 계약 관리

1. **헤더**: 뒤로가기(→ 전체 메뉴), 제목 "계약 관리", 오른쪽 `+ 계약 추가` → 4.10
2. **요약 카드**: 라벨 "전체 계약", 숫자 "N건". 3칸 집계는 `임대 중 · 만료 임박 · 종료`
3. **경고 안내 박스** (만료 임박 계약이 있을 때만): 느낌표 아이콘, 제목 "만료가 가까운 계약이 있어요", 설명 "계약 n건이 120일 안에 끝나요.", 버튼 `해당 계약만 보기` → '만료 임박' 칩을 선택한다
4. **검색 입력**: "건물, 호실, 임차인 이름 검색". 입력하는 즉시 목록을 걸러낸다.
5. **필터 칩**: 전체 N · 임대 중 N · 만료 임박 N · 종료 N (시작 전 계약은 '전체'에서만 보인다)
6. **계약 카드 목록**. 카드 하나의 구성:
   - 윗줄: 문서 아이콘, "101동 1203호"(굵게), 오른쪽에 상태 뱃지(임대 중 / 만료 임박 D-n / 종료 / 시작 전)
   - 제목 아래: 건물명. 임차인 이름을 입력했으면 사람 아이콘과 함께 " · 김○○"
   - 그 아래: "2025-09-01 ~ 2027-08-31 · 월 80만원" (전세면 "· 전세")
   - 구분선
   - 아랫줄: "보증금 50,000,000원"
   - 카드를 누르면 계약 수정(4.10)
   - 정렬: 만료 임박 → 임대 중 → 시작 전 → 종료, 같은 상태 안에서는 종료일이 가까운 순

계약이 없으면 3~6 대신 빈 상태: "아직 등록한 계약이 없어요" / "호실에 계약을 등록하면 만료일을 챙겨드려요." / `첫 계약 등록하기`. 호실이 하나도 없으면 버튼을 `건물 관리로 가기`로 바꾼다.

### 4.10 계약 등록 / 계약 수정

1. **헤더**: 뒤로가기, 제목 "계약 등록"
2. **오류 안내 박스** (필요할 때만)
3. **입력 카드 '계약 정보'**

| 필드 | 동작 |
|---|---|
| 호실 `*` | 호실 상세·호실 카드에서 들어오면 그 호실로 고정(읽기 전용). 계약 관리에서 들어오면 "건물명 동·호" 목록에서 고른다 |
| 계약 유형 `*` | `월세` / `전세` 둘 중 하나를 고르는 버튼. 기본 월세 |
| 보증금 `*` | 원 단위 입력. 아래에 "5,000만원" 식으로 읽어준다 |
| 월세 `*` | 계약 유형이 전세면 이 필드를 숨기고 0으로 저장한다 |
| 시작일 `*`, 종료일 `*` | 날짜 선택. 한 줄에 나란히 |
| 임차인 이름 (선택) | 계약 카드와 호실 화면에 표시하는 용도로만 쓴다 |

4. **폼 버튼 줄**: `취소` · `계약 등록`

검증(어기면 오류 박스로 안내하고 저장하지 않는다):

- 필수값 누락: "호실, 보증금, 계약 기간은 필수예요."
- 종료일이 시작일보다 앞서거나 같음: "종료일은 시작일보다 뒤여야 해요."
- 같은 호실에 기간이 겹치는 계약이 있음: "같은 호실에 기간이 겹치는 계약이 있어요."

저장하면 들어온 화면으로 돌아간다(건물 상세, 호실 상세, 계약 관리 중 하나).

**계약 수정**: 같은 폼, 제목 "계약 수정". 호실은 바꿀 수 없다. 맨 아래 `계약 삭제`는 확인을 받은 뒤 지운다.

DB는 빈 상태로 시작한다. 화면에 나오는 값은 아래 셋 중 하나다.

| 값 | 출처 | 방식 |
|---|---|---|
| 단지명, 주소, 지역코드, 지번 | 기존 단지 검색 | 불러옴 |
| 호실 전용면적, 층 | 기존 면적·층 자동 조회 | 불러옴 |
| 주용도, 구조, 사용승인일, 층수, 세대수, 주차, 연면적 | 건축물대장 API | 불러옴 |
| 참고가, 기간별 실거래 평균, 비교 3가지, 가격 위치 범위, 최근 실거래 | 매매 실거래 API | 불러옴 |
| 매입가 제안값 | 매매 실거래 API(취득 시점 1~6개월) | 불러옴, 사용자가 확정 |
| 주변 전월세 시세 | 전월세 실거래 API | 불러옴 |
| 전월세전환율 | 한국부동산원 R-ONE API, 안 되면 설정값(8.4) | 불러옴 또는 설정 |
| 건물명, 보유 호실 수, 건물 메모 | — | 사용자 입력(건물명은 단지명으로 자동 채움) |
| 동·호, 취득 연월, 매입가 | — | 사용자 입력 |
| 계약 유형, 보증금, 월세, 계약 기간, 임차인 이름 | — | 사용자 입력(공개 자료 없음) |
| 임대 상태, 건물 상태, 입주율, 환산 월세, 내 건물 지표 | — | 위 값으로 계산 |

불러오지 못한 값은 비워 두고 오류나 빈 상태 문구를 보여준다. 임의의 값으로 채우지 않는다.

## 6. 데이터 모델

새 스키마로 빈 DB를 만든다. 기존 자산 테이블과 데이터는 쓰지 않는다. 실거래 캐시 테이블은 기존 것을 그대로 써도 된다.

```
buildings                   건물(아파트 단지)
  id, name, complex_name, address,
  sigungu_code, bjdong_code, bun, ji,
  owned_unit_count (기본 1), description,
  building_spec (JSON), building_spec_fetched_at, created_at

units                       호실 (부동산 자체. 건물 안에서 동·호가 유일)
  id, building_id, dong, ho, area_m2, floor, created_at

unit_holdings               내 보유 정보 (PoC에서는 호실마다 1건)
  id, unit_id, acquisition_ym, purchase_price,
  ownership_status ('UNVERIFIED' | 'VERIFIED', 기본 'UNVERIFIED'),
  registered_at, value_checked_at

leases                      임대 계약 (한 호실에 시간순으로 여러 건)
  id, unit_id, lease_type ('MONTHLY' | 'JEONSE'),
  deposit, monthly_rent, start_date, end_date, tenant_name,
  created_at, updated_at

unit_value_references       참고가 기록 (근거가 바뀔 때만 한 줄 추가)
  id, unit_id, value, source, basis, reference_date,
  transaction_ids (JSON), fetched_at

rent_transactions           전월세 실거래 캐시
  id, sigungu_code, deal_ym, complex_name, jibun, area_m2, floor,
  deposit, monthly_rent, contract_date, contract_type, unique_key

conversion_rates            전월세전환율 캐시
  id, region, ym, rate, source ('RONE' | 'MANUAL'), fetched_at
```

- 금액은 모두 원 단위 정수로 저장한다(API의 만원 단위는 수집할 때 바꾼다).
- 임대 상태, 건물 상태, 입주율은 저장하지 않고 조회할 때 계산한다.
- `ownership_status`는 나중에 소유 인증을 붙일 자리로 컬럼만 둔다. **화면에는 표시하지 않는다.**
- 건물과 호실, 호실과 보유 정보를 나눈 것은 소유자가 바뀌어도 부동산 기록을 유지하기 위해서다.

## 7. 계산 규칙

### 7.1 호실과 계약의 상태

오늘 날짜를 기준으로 호실마다 하나로 정한다.

| 조건 | 호실 상태 |
|---|---|
| 진행 중인 계약이 있고 종료일까지 121일 이상 | 임대 중 |
| 진행 중인 계약이 있고 종료일까지 120일 이하 | 만료 임박 |
| 진행 중인 계약이 없고 시작 전 계약이 있음 | 입주 예정 |
| 그 외 | 공실 |

'진행 중'은 시작일 ≤ 오늘 ≤ 종료일이다. 계약 자체의 상태는 임대 중 / 만료 임박 / 종료(종료일 < 오늘) / 시작 전(시작일 > 오늘).

화면별 집계:

| 화면 | 3칸 | 묶는 방법 |
|---|---|---|
| 건물 상세 통계 타일 | 임대 중 · 공실 · 입주 예정 | 호실 기준. 만료 임박은 임대 중에 포함 |
| 계약 관리 요약 카드 | 임대 중 · 만료 임박 · 종료 | 계약 기준. 시작 전은 전체 건수에만 포함 |

### 7.2 건물 상태와 입주율

| 조건 (위에서부터 먼저 맞는 것) | 건물 상태 |
|---|---|
| 등록한 호실이 없음 | 등록 중 |
| 만료 임박인 호실이 하나라도 있음 | 확인 필요 |
| 그 외 | 운영 중 |

```
입주율 = (임대 중 + 만료 임박 호실 수) ÷ 보유 호실 수
```

진행 막대 오른쪽의 "1/1"은 이 식의 분자/분모다. 등록한 호실 수는 보유 호실 수를 넘을 수 없다(4.5의 등록 현황 박스).

### 7.3 참고가와 갱신

- 참고가 계산은 기존 '현재 추정가' 로직을 그대로 쓴다. 이름과 표기만 바꾼다.
- 기준일 = 계산에 쓰인 거래 중 가장 최근 계약일.
- 갱신 시점: 호실 등록 직후, 자산 분석 상세의 `새로고침`. (실서비스의 월 1회 일괄 갱신은 계획으로만 둔다.)
- 재수집 후 다시 계산했을 때 **근거 거래 묶음이 직전 기록과 다르면** `unit_value_references`에 새 줄을 넣는다. 같으면 새 줄을 넣지 않고 `value_checked_at`만 갱신한다.
- 화면에는 항상 가장 최근 줄을 보여준다.

### 7.4 기간별 실거래 평균과 가격 위치 막대

기간별 실거래 평균:

- 대상: 같은 단지·같은 면적 매매 거래(참고가와 같은 기준)
- 기간: 계약일이 오늘로부터 1개월 / 3개월 / 6개월 이내인 거래. 세 기간은 서로 포함 관계다(6개월 ⊇ 3개월 ⊇ 1개월).
- 값: 평균(만원 단위 반올림)과 건수. 0건이면 "거래 없음"
- 이미 수집한 12개월 데이터로 계산한다. 추가 호출은 없다.

가격 위치 막대(추이 그래프를 대신하는 가로 막대 하나):

- 음영 구간: 같은 단지·같은 면적 최근 12개월 거래의 최저가 ~ 최고가
- 표식 2개: 매입가(라벨 "매입가"), 참고가(라벨 "참고가", 강조)
- 막대 전체 범위: `min(매입가, 참고가, 최저가)` ~ `max(매입가, 참고가, 최고가)`, 양끝에 5% 여유
- 막대 아래 작은 글씨: "최근 12개월 거래 n건 · 최저 5억 8,000만 ~ 최고 6억 4,000만"
- 거래가 1건이면 음영 대신 그 가격에 표식 하나, 0건이면 막대를 숨기고 안내 문구만

### 7.5 환산 월세와 '내 건물' 지표

```
환산 월세 = 월세 + 보증금 × 전월세전환율 ÷ 12
```

- 검산: 보증금 5,000만원 · 월세 0원 · 전환율 4.56% → 19만원. 보증금 5,000만원 · 월세 80만원 → 99만원.
- 전환율은 8.4에서 얻은 값을 쓴다. 화면 주석에는 비율, 지역, 기준월을 같이 적는다. 전환율을 얻지 못하면 환산 월세 관련 행을 숨기고 "전월세전환율을 불러오지 못해 환산 월세를 계산하지 못했어요."를 보여준다.

'내 건물' 카드(4.8): 그 건물에서 임대 중·만료 임박인 호실의 진행 중 계약만 모은다.

| 지표 | 계산 |
|---|---|
| 평균 월세 | 월세의 평균 |
| 평균 보증금 | 보증금의 평균 |
| 환산 월세 | 계약별 환산 월세의 평균 |
| 평균 면적 | 해당 호실 전용면적의 평균 |
| ㎡당 환산 월세 | 환산 월세의 합 ÷ 전용면적의 합 |

검산: 호실 하나, 전용 84㎡, 보증금 5,000만원, 월세 80만원, 전환율 4.56% → ㎡당 11,786원.

### 7.6 주변 전월세 비교

- 대상: 같은 단지 + 비슷한 면적(기존 '비슷한 면적' 기준을 그대로 쓴다)
- 기간: 최근 6개월. 3건 미만이면 12개월로 넓히고, 그래도 3건 미만이면 빈 상태
- 각 거래를 환산 월세로 바꾼 뒤 평균·최저·최고·건수를 구한다
- 차이(%) = (내 환산 월세 − 주변 평균) ÷ 주변 평균. ±3% 안이면 "비슷해요"
- 전월세 실거래 자료에는 동·호가 없으므로 단지·면적·층까지만 맞춘다
- 계약구분(신규/갱신) 값이 응답에 있으면 저장만 하고 걸러내지는 않는다

### 7.7 매입가 제안

- 취득 연월 한 달의 같은 단지·같은 면적 매매 거래 평균을 만원 단위로 반올림해 제안한다. 건수를 같이 보여준다.
- 그 달에 거래가 없으면 취득 연월을 포함해 그 이전 3개월, 다시 없으면 6개월로 넓힌다. 처음 거래가 잡힌 기간의 평균을 제안하고 기간을 문구에 밝힌다.
- 호출은 필요한 달만 한다(1회 → 최대 6회). 이미 수집한 달은 다시 부르지 않는다.
- 제안은 채워 넣기를 도울 뿐이다. 저장되는 값은 사용자가 확정한 매입가다.
- 이 조회는 과거 추이를 불러오는 것이 아니다. 취득 시점 최대 6개월만 부른다.

## 8. 외부 데이터

앱이 외부 API를 직접 부르지 않는다. 서버가 불러와 정규화하고 DB에 저장한 뒤 앱에 준다(기존 방식 유지). 공급자별 코드는 모듈 하나씩으로 나눠 나중에 바꿀 수 있게 한다.

### 8.1 매매 실거래

기존 것 그대로. 시군구 + 계약월 단위, 12개월 재수집 유지. 추가되는 호출은 매입가 제안을 위한 취득 시점 1~6개월뿐이다.

### 8.2 전월세 실거래

- 국토교통부_아파트 전월세 실거래가 자료 (공공데이터포털 15126474, `RTMSDataSvcAptRent/getRTMSDataSvcAptRent`)
- 요청: 법정동코드 앞 5자리 + 계약년월 6자리. 매매 수집과 같은 구조로 최근 12개월을 수집한다.
- 동·호 정보는 제공되지 않는다.
- 같은 시군구·같은 달은 이미 수집했으면 다시 부르지 않는다(가장 최근 달만 재수집).

### 8.3 건축물대장

- 국토교통부_건축HUB_건축물대장정보 서비스 (공공데이터포털 15134735, 표제부 `getBrTitleInfo`)
- 요청: 시군구코드 + 법정동코드 + 본번 + 부번. 건물에 저장한 지번을 쓴다.
- 한 지번에 동별로 여러 줄이 나온다. 주용도가 공동주택인 줄 가운데 지상 층수가 가장 큰 줄을 대표로 쓴다. 관리동·상가 같은 부속 건물 줄이 뽑히면 아파트가 '지상 1층'으로 표시되는 오류가 생기므로 주의한다.
- 세대수·주차 대수가 동 단위로만 나오면 총괄표제부 조회를 시도하고, 그래도 없으면 해당 행을 숨긴다.
- 결과는 `buildings.building_spec`에 저장하고 다시 부르지 않는다(`다시 시도`를 누를 때만 재조회).

### 8.4 전월세전환율

한국부동산원 부동산통계정보(R-ONE) Open API를 쓴다. 인증키는 운영자가 발급받아 `.env`의 `RONE_API_KEY`에 넣는다.

1. 개발 가이드(`https://www.reb.or.kr/r-one/portal/openapi/openApiDevPage.do`)에서 요청 URL과 인자를 확인한다. API는 통계표 검색(`SttsApiTbl.do`), 통계표 항목 조회(`SttsApiTblItm.do`), 통계 데이터 조회(`SttsApiTblData.do`) 세 가지로 알려져 있다.
2. 통계표 검색으로 '전월세전환율' 통계표의 ID를 찾고, 항목 조회로 **서울 · 아파트**에 해당하는 분류·항목 코드를 찾는다. 찾은 ID와 코드는 설정 파일의 상수로 적어 둔다.
3. 월 단위로 가장 최근 값을 조회해 `conversion_rates`에 `RONE`으로 저장한다. 같은 달 값이 있으면 다시 부르지 않는다.
4. 통계표를 찾지 못하거나 조회에 실패하면 `.env`의 `RENT_CONVERSION_RATE`, `RENT_CONVERSION_RATE_YM`을 쓰고 출처를 `MANUAL`로 저장한다. 이때 화면 주석 끝에 "(직접 입력한 값)"을 붙인다. 이 상황은 작업 보고에 반드시 적는다.
5. 둘 다 없으면 7.5의 안내 문구를 보여준다. 임의의 비율을 코드에 넣지 않는다.

### 8.5 호출량

호실 하나를 등록할 때 새로 생기는 호출은 전월세 12회 안팎, 매입가 제안 1~6회다. 건물을 처음 등록할 때 건축물대장 1~2회, 전환율은 한 달에 한 번이다.

## 9. 구현 순서

세 단계로 나눈다. 각 단계는 그 자체로 화면이 깨지지 않게 끝내고, 전체 메뉴에는 그 단계까지 구현된 화면만 올린다.

**1단계 — 건물·호실 구조와 매매 시세**
- 새 스키마(`buildings` / `units` / `unit_holdings` / `unit_value_references`), 빈 DB
- 추이 그래프와 장기 데이터 로드 제거
- 전체 메뉴(건물 관리, 자산 분석), 건물 관리, 새 건물 등록(주소 검색 바텀시트, 등록 방식 전환), 건물 상세, 호실 등록(등록 현황 박스, 등록 방식 전환, 매입가 제안), 호실 상세의 '매입과 시세' 카드
- 자산 분석 목록, 자산 분석 상세의 '매매 시세' 카드(참고가 표기, 기간별 실거래 평균, 가격 위치 막대, 비교 3가지, 최근 실거래, 새로고침)
- 호실 카드는 계약 없는 형태만

**2단계 — 임대 계약**
- `leases`, 계약 등록·수정·삭제, 계약 관리
- 호실 상태, 건물 상태, 입주율, 호실 카드의 계약 있는 형태
- 건물 관리 요약 카드와 칩, 건물 상세 통계 타일과 칩, 호실 상세의 '임대 현황' 카드(환산 월세 제외)
- 전체 메뉴에 계약 관리 추가

**3단계 — 자산 분석 완성**
- 전월세 수집, 전월세전환율(R-ONE), 환산 월세
- 건축물대장 조회
- 자산 분석 상세의 '내 건물', '주변 전월세 시세', '건축물대장' 카드
- 호실 상세 '임대 현황' 카드에 환산 월세 추가

## 10. 만들지 않는 것

아래는 구현하지 않으며, 화면에 메뉴·버튼·뱃지·안내로도 두지 않는다.

하단 탭, 별도의 홈 화면, 운영 내역(수입·지출), 자산 이력, 로그인·회원가입, 소유 인증(뱃지 포함), 수납·청구·입금 확인, 임차인 초대와 임차인 화면, 민원·수리 접수와 업체 배정, 승인, 리포트, 계약 갱신 협의, 공실 관리(별도 화면), 퇴거 정산, 엑셀 내보내기와 대량 등록, 계약서·사진 첨부, 호실의 방 구성·설비 입력, 알림 발송, 요금제 표시, 전체 메뉴 검색, 도로명주소 API 연동, K-APT 연동, 공동소유, 전국 확대와 야간 일괄 수집, 장기(1년 이상) 시세 추이, 데스크탑 화면.

## 11. 확인 체크리스트

검증 자산: 서울 노원구 하계동 아파트, 취득 연월 2016년 10월.

구조와 흐름
- [ ] 빈 DB로 앱을 열면 전체 메뉴가 나오고, 메뉴는 건물 관리·자산 분석·계약 관리 세 개뿐이다
- [ ] 하단 탭이 어느 화면에도 없다
- [ ] 건물 관리가 빈 상태와 `첫 건물 등록하기`를 보여준다
- [ ] 새 건물 등록: 주소 필드를 누르면 바텀시트가 열리고, 결과를 고르면 주소와 건물명이 채워진다
- [ ] `순서대로 등록하기`는 단계별로, `한 번에 등록하기`는 한 화면으로 보이고, 전환해도 입력값이 유지되며 두 방식의 저장 결과가 같다
- [ ] 건물명이나 주소 없이 등록하면 오류 박스가 뜨고 저장되지 않는다
- [ ] 등록 후 건물 상세로 이동하고 성공 박스와 `첫 호실 등록하기`가 보인다
- [ ] 호실 등록: 등록 현황 박스의 숫자가 맞고, 동·호를 넣으면 면적과 층이 채워진다
- [ ] 취득 연월을 넣으면 매입가 제안이 나오고, 그 달에 거래가 없으면 3개월·6개월로 넓혀 기간을 밝힌다
- [ ] 등록 후 건물 상세로 돌아오고, 건물 관리의 건물 상태가 '등록 중'에서 '운영 중'으로 바뀐다
- [ ] 보유 호실 수만큼 등록하면 호실 등록 화면이 `보유 호실 수 늘리기`를 안내한다
- [ ] 같은 단지, 같은 동·호를 다시 등록하면 막힌다

계약과 상태
- [ ] 계약이 없는 호실은 참고가가 큰 카드로, 계약을 등록하면 임대 상태가 위에 오는 카드로 바뀐다
- [ ] 종료일이 120일 이내인 계약을 넣으면 호실 뱃지 '만료 임박 D-n', 건물 상태 '확인 필요', 계약 관리 경고 박스가 모두 맞게 나온다
- [ ] 기간이 겹치는 계약, 종료일이 시작일보다 앞선 계약은 저장되지 않는다
- [ ] 입주율과 "n/n" 표시가 7.2의 식과 맞는다
- [ ] 임차인 이름을 넣으면 계약 카드와 호실 화면에 보이고, 비우면 자리가 남지 않는다

자산 분석
- [ ] 자산 분석에 들어가면 건물 목록이 먼저 나오고, 건물을 누르면 상세가 나온다
- [ ] 참고가 옆에 기준일과 근거 건수가 보이고, 값이 기존 '현재 추정가' 로직의 결과와 같다
- [ ] 기간별 실거래 평균의 1·3·6개월 값과 건수가 DB의 매매 거래로 직접 계산한 값과 같다
- [ ] 비교 3가지가 기존 PoC와 같은 방식으로 나온다
- [ ] 새로고침을 연속으로 눌러도 근거 거래가 같으면 참고가 기록이 늘지 않는다
- [ ] 가격 위치 막대에서 2016년 매입가가 최근 거래 범위 왼쪽 바깥에 찍힌다
- [ ] 보증금 5,000만원·월세 0원·전환율 4.56%일 때 환산 월세가 19만원으로 나온다
- [ ] 주변 전월세 건수와 평균이 DB의 전월세 거래로 직접 계산한 값과 같다
- [ ] 건축물대장 카드의 층수가 실제 아파트 층수와 맞다(1층으로 나오지 않는다)
- [ ] 전환율 주석에 비율·지역·기준월이 보이고, R-ONE에서 받은 값인지 설정값인지 구분된다

범위
- [ ] 화면 어디에도 '준비 중', 미인증 뱃지, 추이 그래프, 동작하지 않는 버튼이 없다
- [ ] 코드와 DB에 시드·샘플 데이터가 없다
- [ ] 모든 화면이 모바일 폭에서 가로 스크롤 없이 보인다

## 12. 운영자가 미리 준비할 것

1. 공공데이터포털 활용신청 2건: '국토교통부_아파트 전월세 실거래가 자료', '국토교통부_건축HUB_건축물대장정보 서비스'. 승인 후 `.env`에 키를 넣는다(기존 키와 같은 계정이면 같은 키로 호출되는지 확인).
2. R-ONE 인증키(발급 완료)를 `.env`의 `RONE_API_KEY`에 넣는다.
3. R-ONE에서 전환율을 받지 못할 때를 대비해, 통계에서 확인한 값과 기준월을 `.env`의 `RENT_CONVERSION_RATE`, `RENT_CONVERSION_RATE_YM`에 넣어 둔다(선택).
